# Phase 3 Tools, Files and Documentation Test Report (2026-08-15)

>Rerun: `uv run pytest` (70 passed, 2 skipped)
> Phase 3 exit conditions: All test corpus covering the format will give proven results; high-risk actions cannot bypass approval.

## 1. Permissions, approval and auditing (policy/)

- `PolicyEngine`: tool name → risk level deterministic rule; unknown tools are always `BLOCKED`.
  Read-only `auto`, low-risk write `session`, medium/high/delete `once`, bulk delete `blocked`.
- `ApprovalService`: short-term one-time approval number (`secrets.token_urlsafe`),
  Not replayable (`used_count`), 10 minutes expiration, session binding verification,
`once/session` scope is strictly matched to prevent low-privilege approval from downgrading approval of high-risk tools.
- `SessionGrant`: Low-risk writes are granted per session (24h).
- `AuditService`: records the executor, parameter summary, approval id, decision, result and time of each actual action;
  The `content` in the parameter only remembers the length, not the full text.
- DB migration `0003`: approvals/session_grants/audit_events.
- Red team test coverage: unknown tool rejection, batch deletion cannot be bypassed, once code replay rejection,
  Session approval cannot approve once tools and parameters are illegal and will be rejected before execution.

## 2. Tool layer (tools/)

| Tools | Risk | Behavior |
|---|---|---|
| `file.read` | Read-only | UTF-8 → GB18030 → latin-1 encoding fallback; native full file range |
| `file.create` | Low risk | Create a new file; not overwritten by default; session authorization required |
| `file.write` | Medium risk | Only overwrite existing files; approved one by one |
| `file.move` | Medium risk | Move/rename; approval on a case-by-case basis |
| `file.delete` | Delete | A single file is moved to the Trash via Finder, and permanent deletion is prohibited |
| `file.batch_delete` | Batch deletion | PolicyEngine directly rejects, the executor has no execution path |
| `screen.capture` | Read-only | `screencapture -x`; truthfully report errors when permissions are missing |
| `web.search` / `web.fetch` | Read-only | Results preserved URL/title/summary, content marked `untrusted` |
| `document.parse` | Read-only | Distributed to document parser, source is local path |
| `archive.list` | Read-only | Only lists zip/tar entries and estimated sizes, no decompression |

- `ToolExecutor` is the only execution entry: model output can only be given by tool name + parameters.
PolicyEngine → Approval → Schema Validation → Execution → Audit, no step can be skipped.

## 3. Document parsing (documents/)

Measured corpus (temporary directory generated and all sources):

| Format | Result |
|---|---|
| UTF-8 / GB18030 text, Python code | Text + encoding + truncation mark |
| PDF (generated by PyMuPDF) | Page text, page number, scanned page OCR mark |
| DOCX / XLSX / PPTX | Paragraph/Table/Sheet/Slide Text |
| Image OCR (Apple Vision) | Rendered PNG identifying "WHITE NIGHT 42" with confidence |
| ZIP | Only entries and decompression estimates are listed, actual measurements do not include decompression |
| Old version .doc/.xls/.ppt | Report errors clearly and use controlled converter (no automatic conversion) |
| Unknown format | Report errors truthfully and do not forge content |

Scan PDF: Pages with text size <20 characters are automatically rendered at 200 DPI followed by Apple Vision OCR,
Mark `ocr_failed_pages` in metadata when OCR is unavailable/failed.
